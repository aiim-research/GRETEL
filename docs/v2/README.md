# Protocol v2: experiments without padding

Protocol v2 (decided on 3 November 2026, task 0 of the research plan) runs every graph at its own size. In v1, variable-size datasets are padded with empty nodes up to the largest graph of the dataset. That made the oracles depend on the padding (a GCN that averages over all nodes reads the amount of padding), let the explainers edit nodes that do not exist (edges to padding rows flip the oracle: from 20 % to 50 % of the counterfactuals of AIDS, BBBP and PROTEINS in the selector study touched them) and kept the metrics from charging nodes. v2 removes the padding instead of patching around it.

v1 stays as it is. The same code runs both protocols, and nothing of v1 changes: every v2 feature is opt-in, and the v1 configs keep their hashes, their caches and their numbers.

## What v2 guarantees

- **Every node is real.** No AdjacencyMatrixPadder: a graph's matrix is its own size, the minimizers search only its node pairs, and the oracles never see padding (they are trained again, without it).
- **Seeds inside the input's node set.** Generators that return another graph of the dataset (DCE, DCM) return the nearest candidate whose projection onto the input's nodes is a counterfactual (`projection`: `index` or `assignment`, `src/explainer/future/utils/projection.py`). The minimizer starts from a valid seed, and whatever it returns stays inside the input's nodes.
- **A measure that charges nodes.** `src/utils/metrics/correspondence.py` defines the edit cost of a pair under an explicit node correspondence: node insertions and deletions, edge edits (incident edges of inserted or deleted nodes included) and the feature distance of the mapped nodes, with the costs as parameters. Its stages (`edit_distance.EditDistance`, `StructuralEditDistance`, `MatchedFeatureDistance`) run after the cell-wise GED, which stays for comparison with v1. This is the first step towards the unified metric of line B1, not that metric yet.
- **GCN oracles with the layers their config asks for** (`exact_conv_layers`; v1 builds at most two convolutions).

## What is v1 only

The explainers that need every graph at one size declare `requires_fixed_size` and stop with a clear error on a dataset of several sizes: RSGG, GCounteRGAN, EAGER, CLEAR, CF2, DDBS, and DFS and DBS (their priors are per node index). They keep running on padded datasets and on fixed-size ones (ASD, Tree-Cycles), in v1 and in v2.

## Where things are

- `lab/config/v2/`: the configs and the snippets they compose, generated by `scripts/gen_v2_configs.py` from the v1 configs (its docstring gives the transformation). Do not edit them: change the v1 config or the script and regenerate. Index: `CONFIGS.md`.
- Scopes, selector model tags, checkpoints and collections carry `v2-` or a `v2/` folder, so v2 never reads or overwrites a v1 artefact. The dataset and oracle caches separate by themselves, because their hashes change.
