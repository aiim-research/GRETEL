# Protocol v2 sondeo on the server

Fold 0 of every first-paper cell of `lab/config/v2` (the thesis and paper-revision comparisons, BLS-F included): 152 configs in two phases, generated by `scripts/gen_v2_queues.py`. It checks that the first paper's comparisons run without padding and gives their first v2 numbers. The selector paper's v2 cells (`*-sel`) are left to its own fleet: selector_v1 needs v2 collections and checkpoints first.

| Queue | Configs | Content |
|---|---|---|
| `SONDEO_A.md` | 25 | the generators alone (`*-dummy`), which fill the shared generator cache: one seed per instance and fold, decided by the generator, for every minimizer |
| `SONDEO_B.md` | 127 | every minimizer (BLS and its variants, BLS-F, OBS, RHC, the PI4 budgets) from those seeds |

The dataset caches, the oracles (retrained without padding, with the GCN layers their configs ask for) and the DCEM medoids come committed from the local smoke of every v2 cell (`tests/regression_smoke.py --tree lab/config/v2/generate_minimize --discover`), so no warm job is needed and every clone uses the same oracles. The generator outputs are not committed: phase A builds them on the server.

Rule: on the server only Slurm jobs compute. Everything below only syncs git, submits, or reads logs.

**Step 0. Once: the `dev` branch on the server's clone.** Switch only when no job of the clone is queued or running: a task that starts after the switch runs the new branch's code. The TU raw data the clone already has (`data/working`) stays.

```bash
cd ~/projects/GRETEL && squeue -u $USER                 # empty before switching
git fetch && git switch dev && launchers/server_sync.sh
```

**Step 1. The sondeo**, both phases in one submission (B starts when A has ended):

```bash
cd ~/projects/GRETEL && launchers/server_sync.sh && conda activate GRTL
launchers/slurm_submit.sh -p normal -m 10 -c docs/v2/SONDEO_A.md docs/v2/SONDEO_B.md
squeue -u $USER                                                    # empty: the sondeo is over
grep -lE "exit status [1-9]|Traceback" output/logs/*/*/fold0_*.out   # failed configs, if any
```

A phase that ends with failures is submitted again as it is: finished configs are skipped. Expected duration: phase A is dominated by DCE's ranking of the candidates (one Hungarian assignment per candidate and instance) and phase B by the minimizers' budgets; the local smoke of one instance per cell gives the per-instance times to scale by the fold size.

**Step 2. Back home**, on the local machine:

```bash
rsync -av kalifano:projects/GRETEL/lab/output/results/v2-* lab/output/results/
rsync -av kalifano:projects/GRETEL/output/logs/ lab/output/server_logs/ && python scripts/collect_logs.py lab/output/server_logs
git add lab/output/results/v2-* lab/output/queue_logs && git commit -m "Protocol v2 sondeo: fold 0 of the first paper's cells" && git push
```

The first reading: the generators' correctness (1 for DCE and DCEM by construction, the fallback count apart), and for each cell the order of the minimizers under `StructuralEditDistance`, `MatchedFeatureDistance` and `OracleCalls`, next to the v1 numbers of the same cells, to check that the first paper's conclusions hold.
